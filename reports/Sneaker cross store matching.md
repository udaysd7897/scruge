# Match sneakers on code, colour order, gender

A sneaker match should be decided by a **three-tier identity key**: brand plus model plus colourway plus gender/age. Tier 1 is an equal full brand style code. Tier 2 is an equal model number or base code plus the same ordered colours plus the same gender. Tier 3 is model-name tokens plus colours plus gender, confirmed by the one-call photo check. The apparel cascade (gate, retrieve, veto, score, photo, confident only with photo plus MRP or manufacturer) carries over unchanged. What has to change is the sneaker-specific parsing that feeds it. The coordinator's live probe of the user's three Amazon.in links (2026-11-13) found that **all three failures happen before matching starts**. Bacca Bucci was searched as "bacca bucci leather white" although Amazon states Model Name "Stride Eclipse" and colour "Black and White". Sparx's style code SM-734 was thrown away because the parser demands four digits. The Nike Killshot record had no brand field, so no query ran at all ([Amazon B0CVF22V83](https://www.amazon.in/dp/B0CVF22V83); [Amazon B09PVFDLSK](https://www.amazon.in/dp/B09PVFDLSK); [Amazon B00770CB12](https://www.amazon.in/dp/B00770CB12)). Each fix below is small and lives in `app/extract.py`, `app/normalize.py`, `app/queries.py`, `app/matcher.py`, `app/vision.py` or `app/sources/flipkart.py`. Flipkart is identifier-rich: footwear carries a spec row "Article Number" ([Flipkart Nike Court Vision](https://www.flipkart.com/nike-court-vision-lo-nn-sneakers-men/p/itm7f1dabd26d2ff)). Myntra exposes no brand code at all, so Myntra matches will mostly reach tier 3 and depend on the photo, MRP and manufacturer ([Myntra Sparx 24338176](https://www.myntra.com/casual-shoes/sparx/sparx-men-round-toe-textile-sneakers/24338176/buy)). Expect the exact-colourway tier to be precise but incomplete. When it misses, the honest answer is "same model, other colours", never a guessed match.

## All three example failures trace to parsing, not scoring

The probe shows Amazon already gives most of what is needed. The app simply reads it wrongly. The table maps each observed bug to the line of code that causes it.

| Example | Observed bug | Root cause in code |
|---|---|---|
| Bacca Bucci B0CVF22V83 | family = "leather" | `from_amazon` builds a sneaker family from `model_line(title)`. "Men Leather Sneaker Shoes" leaves only "leather" once gender and type words are stripped. |
| Bacca Bucci | Model name not queried | `_amazon_model_name` parses "Bacca Bucci Stride Eclipse", but `queries.ladder` uses `model_name` only for `Category.APPAREL`. It also keeps the brand words inside the name. |
| Bacca Bucci | Base colour "white" for "Black and White" | `_base_colour_words` splits on `/ - , &` but not on "and". It then takes the *last* colour word (an apparel "head noun" rule). |
| Bacca Bucci and Sparx | Gender not read from Department "mens" | `_gender` matches `\bmen\b`, and "mens" fails that word boundary. |
| Sparx B09PVFDLSK | SM-734 not extracted | `style_code_like` requires at least 4 digits. `_code_groups` (Flipkart code rung) and `same_style` (`_digit_groups` needing a group of 4 or more) inherit the same limit. | Sparx | Query "sparx stylish white" | The family comes from marketing words. Colour comes from the Colour field (White), while the title says Blue. |

Fixing these rows alone turns the Bacca Bucci query into "bacca bucci stride eclipse" and the Sparx query into "sparx sm 734". Both are exactly the searches that returned the right Flipkart listings in the probe ([Flipkart "bacca bucci stride eclipse"](https://www.flipkart.com/search?q=bacca%20bucci%20stride%20eclipse); [Flipkart "sparx sm-734"](https://www.flipkart.com/search?q=sparx%20sm-734)).

## Identity tiers replace the single style-code check

Large brands give every colourway its own code, and every gender/age version its own model root. The Dunk Low "Panda" in one White/Black colourway has five codes: men's DD1391-100, women's DD1503-101, GS CW1590-100, PS CW1588-100 and TD CW1589-100 ([Sole Retriever](https://soleretriever.com/sneaker-release-dates/nike/dunk-low/nike-dunk-low-white-black-dd1391-100)). The probe's Flipkart search for "nike killshot 2" shows the same structure in India. 432997-107 is the men's Killshot 2 Leather in White, and 432997-070 is the same shoe in Black. FZ5630-101/-001 is the women's "W KILLSHOT 2", and HQ3489-010 is a Killshot 2 PRM edition ([Flipkart search](https://www.flipkart.com/search?q=nike%20killshot%202)). A full code therefore pins model, colourway and gender at once. A shared base code proves only the model, and a different base code with the same name usually means a different gender or edition.

The tiers follow from that. **Tier 1 (exact)** needs equal full codes after normalisation. Uppercase the code, strip `[-_ ./]`, and compare. `1011B962.402` equals `1011B962-402`, because Flipkart writes Asics codes with a dot ([Flipkart Asics](https://www.flipkart.com/asics-gel-pulse-16-running-shoes-men/p/itm0d006f0f3cd41)). Tier 1 is confident without the photo, except in one case. Flipkart's Article Number can be wrong at colour level: a Puma Axis SL listed 36846601 while every image filename said `368466-13-…-white-glacier-gray` ([Flipkart Puma Axis SL](https://www.flipkart.com/puma-axis-sl-sneakers-men/p/itmfd98yaxyexhuh)). So when the Brand Color or the image filename contradicts the code's colour, demote the match to tier 2.

**Tier 2 (model match)** needs an equal base code or model number, colours that agree under the ordered rule below, and agreeing gender. It is confident only after the photo check plus equal MRP or the same manufacturer, which is the existing apparel rule. **Tier 3 (name match)** applies to listings with no usable code: all of Myntra, and code-less Flipkart listings such as the four Bacca Bucci Stride Eclipse colourways. It needs the same model-name tokens, with numeric tokens equal and never fuzzy ("Wonder-13" is not "Wonder-11"). It also needs ordered colours, gender, a photo "same", and MRP or manufacturer agreement.

Per-brand normalisation has to be brand-scoped, because SKU formats collide across brands ([SoleSearch API](https://www.github.com/SoleSearch-Demos/api)). The global patterns are as follows. Nike is `[A-Z]{2}\d{4}|\d{6}` plus a 3-digit colour, with base = the first 6 characters. Puma is 6 digits plus 2, written `37491505`, `374915-05` or `374915_05`. Adidas is `[A-Z]{1,2}\d{4,5}`, with the whole code colour-specific and no separable base. Asics is `1\d{3}[A-Z]\d{3}` plus a 3-digit colour, and its prefix carries gender (1011 men's, 1012 women's), so men's and women's never share a base. Flipkart's meta description often truncates to the base (DH2987, 374915). Treat a meta-only code as base-level ([Flipkart Puma Suede](https://www.flipkart.com/puma-suede-classic-xxi-sneakers-men/p/itm59d0d9bef5d1f)).

Indian brands need a looser rule, and Sparx proves it. Its customer-facing model "SM 323" is filed on Flipkart under Article Number SD0323G. The same page's image filenames carry `sd03230g`, `sd0323g` and `sm323gg` ([Flipkart Sparx SM 323](https://www.flipkart.com/sparx-sm-323-stylish-comfortable-sneakers-men/p/itm591cf2de69726)). The probe shows SM-734 behaving identically: sellers file SD0734G, A1SD0734G-WHGY, a seller SKU I0071328, or nothing, but **the digit group 734/0734 is shared**. For a brand in an `INDIAN_DIGIT_BRANDS` table (Sparx, Campus, Red Tape, Asian, Bacca Bucci), the rule is: extract digit runs of 3 or more, strip leading zeros, and call two codes the same model when their core digit group is equal and the brand is equal. "Same model" is tier 2, not tier 1, because the trailing letters (G, A, -WHGY, -09) encode colour or a seller variant inconsistently. A code with no shared digit group, such as I0071328, is ignored rather than used to veto. That matches the existing `CODE_BRANDS` principle, under which non-brand codes may prove a match but never disprove one. Campus (22G-13407 per colourway) and Red Tape (RSL1255 white-grey vs RSL1258 black) use a different base number per colour. For those two brands, an equal digit group is closer to exact, but keep it at tier 2 until the labelled set shows otherwise ([Flipkart Campus Cipher](https://www.flipkart.com/campus-cipher-sneakers-men/p/itmb76b697fcb8a3); [Flipkart Red Tape](https://www.flipkart.com/red-tape-low-cut-sneaker-men-white-grey-sneakers/p/itm4cc3fbfad3994)). Bacca Bucci's `BBMH9103A-09` fits the pattern `BBMH` + 4-digit model + variant letter + `-NN`. Whether `-NN` is colour or size-run is unverified. The probe found no code on the Flipkart Stride Eclipse listings anyway, so Bacca Bucci falls to tier 3.

## Colours must be compared as an ordered set, not one word

Sneaker colour fields name several colours, and the order carries meaning. Nike's "Colour Shown" lists the upper/base colour first and accents after ([nike.com/in Air Max Plus](https://nike.com/in/t/air-max-plus-shoes-BRVkLx)). Flipkart's Bacca Bucci colourways, "Black, White", "Black, Blue", "Grey, White" and "White, Brown", are separate products that differ only in that pair ([Flipkart search](https://www.flipkart.com/search?q=bacca%20bucci%20stride%20eclipse)). Even GOAT's single "Main Color" facet disagrees with its own colourway text (cream vs white vs tan) ([GOAT Gel NYC](https://www.goat.com/en-de/apparel/asics-gel-nyc-sneaker-cream-white-1203a383-113)). So `Canonical` should carry `colours: tuple[str, ...]`, an ordered list of base families, alongside `base_colour = colours[0]`.

Parsing follows four rules. First, split on `/ , & -` and the word "and", and map each part to a base family. That gives "Black and White" → (black, white), not "white". Second, drop sole-only words before mapping: gum, gum yellow, gum light brown, icy and translucent. Third, add sail, summit white, bone, ecru, off-white and coconut milk to white. That gives "Sail/Gum Yellow/Midnight Navy" → (white, navy), not "yellow". Fourth, read multi-letter brand abbreviations such as `FTWWHT/CBLACK/GRETWO` from Adidas Brand Color and `WHGY` from Sparx seller codes ([Flipkart Adidas Flowsoft](https://www.flipkart.com/adidas-flowsoft-sneaker-sneakers-men/p/itm192f03a6920c9)).

The colour veto becomes: **reject when both sides list two or more colours and the sets differ**, or **when the primaries differ and the single colour on one side is absent from the other side's set**. "Black and White" against "Black, White" passes. Against "Grey, White" or "White, Brown" it fails, which leaves exactly one Bacca Bucci colourway for the photo. "White" against "White, Grey" passes, since a single colour is a subset. Order is only a tie-breaker, not a veto. "Black and White" against "White, Black" passes the gate, and the photo decides which colour is the upper. Inverted pairs are the classic near-duplicate trap, and they are best caught by comparing logo colour against upper colour in the image. "Multicolour" passes anything but scores low.

When Amazon contradicts itself, as Sparx does with Colour "White" and title "Men Blue Stylish Sneakers", reuse the apparel neckline rule: **contradicting fields make the colour unknown for vetoing**. Keep both as an allowed set {white, blue} for ranking, and let the photo decide.

## Gender and age need their own gate, and sparse records need the brand site

Gender and age are invisible in photos. Women's and men's releases of one colourway often cannot be told apart from outside, and GS versions keep the adult design with only subtle differences ([Outsole.nl](https://www.outsole.nl/blog/the-differences-between-mens-and-womens-sneakers/)). So the gate must be text. Parse a segment from every source: Amazon Department ("mens", "womens", "boys", "girls", "unisex"), title words, Flipkart "For Men"/"For Women" and "Ideal for", the Nike "W " title prefix and "WMNS", "GS/Older Kids/Big Kids/Junior/Youth", "PS/Little Kids", "TD/Toddler/Infant", and Myntra `analytics.gender`. Map them to M, W, U, KIDS_BIG, KIDS_LITTLE and KIDS_TODDLER. U matches M or W, and kids never match adult. Nike India labels its kids versions "Older" (for example HV6003-131), so add that word too ([nike.com/in C1TY Older](https://nike.com/in/t/c1ty-older-shoes-pbSF5g/HV6003-131)). When the signals conflict, the segment becomes unknown and does not veto, but the result carries a warning.

The Killshot record is exactly that conflict: title "Boys", breadcrumb Men's Shoes, size 5.5 UK, and the colourway of the adult men's 432997-107. Size is a tie-breaker only. A listing whose sizes all sit at UK 5.5 or below leans kids, but GS and women's sizes overlap, so size alone must never veto. The right output is the adult 432997-107 as a match with a visible note ("Amazon calls this Boys; Flipkart lists it as Men's, check your size"), not a silent veto.

Sparse Amazon records need a fallback chain, because the Apify junglee record for B00770CB12 had only a title, price, size and colour. First, take the brand from the title's leading tokens against a known-brand list (Nike, Adidas, Puma, Asics, Skechers, New Balance, Reebok, Sparx, Campus, Red Tape, Bacca Bucci, Asian, and so on). This also strips the duplicated "Nike Boys Nike". Second, take the model from the title remainder: "Killshot 2 Leather". Third, for brands whose site answers plain requests, resolve the style code from model name plus colour. Nike India product URLs end in the style code (`…/DH2987-101`), and pages show "Style" next to "Colour Shown" ([nike.com/in Court Vision](https://www.nike.com/in/t/court-vision-low-next-nature-shoes-N2fFHb/DH2987-101); [nike.in Court Shot](https://www.nike.in/nike-court-shot-men-s-shoes/p/24942536)). Searching nike.com/in for "killshot 2 leather" and picking the colourway whose Colour Shown starts with "Sail" and contains "Midnight Navy" yields 432997-107. That promotes Killshot to tier 1 against Flipkart. Puma's site already works this way in `brandsite.py`: the style is in the URL path and the colour is in `?swatch=NN` ([in.puma.com 404690](https://in.puma.com/in/en/pd/slipstream-sportstyle-sneakers/404690?swatch=01)). If the brand site is blocked, the Flipkart search itself is the fallback lookup. Among the "nike killshot 2" hits, the gender gate removes FZ5630, the one-sided "PRM" edition token marks HQ3489 as unclear, and the colour gate removes 432997-070. Only 432997-107 survives for the photo check.

## Retrieval must collapse sizes; the photo check must look at shoes, not collars

Flipkart lists a separate `pid` per size, with the size inside the title, "(White , 10)" ([Flipkart Axis SL](https://www.flipkart.com/puma-axis-sl-sneakers-men/p/itmfd98yaxyexhuh)). Without de-duplication, the five photo-check slots fill with sizes of one shoe and push out the other colourways. Strip the trailing `\((colour)\s*,\s*[\d.]+\)` tail before family parsing. Then group candidates by (`itm` id) or, failing that, by (brand, normalised full code or digit group, ordered colours, cleaned title), and keep the in-stock member with the lowest price. The same grouping fixes "size number in family".

The Flipkart code rung should run for sneakers with the right category word: `brand + ' sneakers'` or `' shoes'`, not `' t-shirt'`. It should also accept brand-scoped 3-digit groups, so that `734` finds `sd0734g` in card image filenames. Image filenames on Flipkart carry the code and colour (`368466-13-puma-white-glacier-gray-original-…`). But galleries mix in sibling colourways, so read the code from the first image only ([Flipkart Puma Axis SL](https://www.flipkart.com/puma-axis-sl-sneakers-men/p/itmfd98yaxyexhuh)). For Myntra, search brand plus model name plus gender. Myntra's own titles sometimes omit the model entirely ("ADIDAS Men Striped Sneakers"; "Sparx Men Round Toe Textile Sneakers"). There, the photo plus the MRP and manufacturer/seller agreement (for example, "RELAXO FOOTWEARS LIMITED" against Amazon's Relaxo) carry the match ([Myntra Adidas 47326676](https://www.myntra.com/casual-shoes/adidas/adidas-men-striped-sneakers/47326676/buy); [Myntra Sparx 24338176](https://www.myntra.com/casual-shoes/sparx/sparx-men-round-toe-textile-sneakers/24338176/buy)).

The one-call photo check keeps its shape: shuffled top 5, per-candidate attribute table, and code-side recomputation of the verdict. Shuffling matters, because image order alone flips about 25–30% of multi-image predictions ([arXiv 2503.13792](https://arxiv.org/html/2503.13792v1)). LLM judges also over-trust titles and miss image differences, so keep titles out of the visual judgement ([arXiv 2510.20632](https://arxiv.org/pdf/2510.20632)). For sneakers, `ATTRS` should replace neck/sleeve/stripes/print with seven rows. Silhouette (low/mid/high, toe and tongue shape) and panel layout (overlays, eyestay, toe cap, heel tab, perforations) decide the model. Brand mark (type, position and its colour), upper colour and material, accent colours by zone, midsole/outsole (shape and colour, gum vs white), and laces decide the colourway. Add a `view` field per image (lateral, medial, top, pair, on-foot), because a medial side shows a smaller logo and can look like a mismatch. The code rule is: "same" only if silhouette, panels and brand mark match, at least two of upper/accents/sole match, and nothing mismatches. "Different" follows any mismatch in silhouette, panels or a clear colour row. Everything else, including a sail-vs-white difference alone, is "unclear". Name the known traps in the prompt: inverted colour pairs, sail vs white, gum vs white sole, PRM/SE material editions, and medial views. Images should be about 1,000 px. Claude is unreliable under 200 px, and logos and stitch lines blur at thumbnail sizes, so move `small_image` to Amazon `_SL1000_`, Flipkart `/image/832/832/` and Myntra `w_1080`. That costs roughly 1,300 tokens per image ([Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)).

When no exact colourway exists, show tiers rather than nothing. A candidate that passes brand, model, gender and edition gates but fails colour belongs in a "Same model, other colours" list, with its colour names. For Bacca Bucci that would read: "Stride Eclipse also in Black/Blue, Grey/White, White/Brown". A candidate that passes everything but where the photo says "different" stays in the existing "Not listed — closest options" list. Gender-mismatched versions (the women's W KILLSHOT 2) never appear as the same model; at most they appear as a one-line "women's version exists" note. A sneaker app that says "this model, not in your colour" earns more trust than one that silently returns the white pair for a black request.

## Conclusion

The apparel work already built the right machinery. Sneakers break it only because their identity sits in different fields: Model Name instead of neckline, an ordered colour pair instead of one colour, and a gender/age segment that changes the style code. The practical consequence is that most precision gains here are cheap. Ten parsing and gating changes cover every failure seen in the three links before any model is involved, and the photo check becomes a tie-breaker between one or two survivors rather than a search.

Two unknowns should guide what comes next. The Indian-brand digit-group rule rests on two Sparx models, and it has not been tested for collisions across a brand's full catalogue. And no one has measured how well the photo check separates inverted colour pairs on Indian marketplace photos. A labelled set of about 100 Amazon-to-Flipkart/Myntra sneaker pairs, half of them same-model-other-colour hard negatives, will settle both. It is worth more than any further prompt tuning.
